
# 📑 Отчет: Интеграция COM-порта и анализ протокола передачи данных

## 1. Структура транспортного кадра
В ходе анализа документации и перехвата реального трафика (сниффинга) была установлена точная бинарная структура пакета, используемого устройством для передачи данных по каналу (115200 бит/с).

Каждый пакет имеет следующую структуру:

| Байты в кадре | Название | Техническое назначение |
|--------------|----------|------------------------|
| `00 75 00` | **Заголовок / Маркер начала** | `0x00` (NULL), `0x75` (ASCII `'u'`), `0x00`. Уникальная "шапка" кадра. Позволяет приемнику определить начало нового пакета в потоке байт. |
| `FF F0 0F` | **Синхробайты (Sync)** | Магическая последовательность для точного выравнивания. Гарантирует, что данные не будут прочитаны со смещением даже при помехах в эфире. |
| `[Signal_Byte]` (1 байт) | **Уровень сигнала (RSSI)** | Числовое значение `0–255`. Показывает качество радиосвязи в момент отправки. Используется для фильтрации слабых сигналов. |
| `[Data_ASCII]` | **Полезные данные** | ASCII-строка в формате CSV. Содержит те же поля, что и текстовые файлы (`ID, UTC time, state...`). Может содержать несколько строк, разделенных `\n`. |
| `00` | **Терминатор** | Нуль-байт (`\0`). Четко обозначает конец полезной нагрузки. |

**Полная схема:**
`[00 75 00] [FF F0 0F] [RSSI] [CSV_DATA...] [00]`

### Почему это важно?
1. **Надежность:** Преамбула и синхробайты позволяют автоматически восстанавливать синхронизацию после потерь данных в радиоэфире.
2. **Диагностика:** Выделенный байт RSSI позволяет оценивать качество покрытия без декодирования самих координат.
3. **Совместимость:** Внутри бинарной оболочки находятся обычные текстовые строки, которые уже успешно обрабатываются существующим парсером `importer.py`.

## 3. Инструкция по запуску и настройке

### Шаг 1: Подготовка окружения
Для работы требуется Python 3.8+ и библиотека `pyserial`.

1. Создайте виртуальное окружение:
   ```bash
   python -m venv venv
   ```
2. Активируйте его:
   *   **Linux/macOS:** `source venv/bin/activate`
   *   **Windows:** `venv\Scripts\activate`
3. Установите зависимости из файла `requirements.txt`:
   ```bash
   pip install -r requirements.txt
   ```

### Шаг 2: Поиск устройства
Подключите приемник к компьютеру и определите имя порта.

**Для Linux (Bash):**
```bash
ls /dev/tty[S,USB,ACM]*
```
*Обычно USB-адаптеры появляются как `/dev/ttyUSB0` или `/dev/ttyACM0`.*

**Для Windows (PowerShell):**
```powershell
Get-CimInstance Win32_SerialPort | Select-Object DeviceID, Description
```
*Ищите порты вида `COM3`, `COM4` и т.д.*

### Шаг 3: ⚠️ !ВАЖНО! ⚠️ Настройка прав доступа (Только Linux)
В Linux обычные пользователи не имеют доступа к COM-портам. Для быстрого теста используйте команду `sudo`:

```bash
sudo chmod 666 /dev/ttyUSB0
```
*(Замените `/dev/ttyUSB0` на ваш порт, если он отличается).*

> **Примечание:** Для постоянной работы рекомендуется добавить пользователя в группу `dialout` командой `sudo usermod -aG dialout $USER` (требуется перелогиниться).

### Шаг 4: Запуск валидации
Запустите скрипт сниффера, указав найденный порт:

**Linux:**
```bash
python validate_sniffer.py --port /dev/ttyUSB0 --baud 115200 --max 10
```

**Windows:**
```powershell
python validate_sniffer.py --port COM3 --baud 115200 --max 10
```

Если вы видите вывод с полями `sensor_id`, `latitude`, `longitude` — подключение настроено верно, и устройство передает данные в ожидаемом формате.

## 4. Дальнейшие шаги
Так как структура данных подтверждена и парсинг работает стабильно, следующим этапом будет внедрение класса `SerialImporter` в основной проект. Он будет:
1. Читать поток в реальном времени.
2. Очищать данные от бинарных заголовков.
3. Передавать готовые словари в Redis-батчи для сохранения в БД тем же способом, что и файлы из папки `indata`.
